The error term

Why the line steps up exactly when it does — traced on your own code's shallow test case, (0,0) → (5,2).

The problem in one picture

A screen has no true diagonals, only whole pixels. The true line from (0,0) to (5,2) climbs 0.4 cells per column, so after each step right we must decide: stay flat, or step up diagonally? Bresenham's answer is to carry a single integer, the error, that tracks how far the true line has pulled away from the pixels so far — no floats anywhere (Wikipedia; step-by-step walkthrough).

The setup in your code

shapes/line.go, Points(), for A=(0,0), B=(5,2):

dx = |5-0| = 5        dy = -|2-0| = -2   # dy stored negative
sx = 1                sy = 1             # heading right and down-screen
err = dx + dy = 3                        # the running error

Each tick computes e2 = 2*err. Doubling is the whole trick: the real question is "has the line drifted more than half a cell?", and doubling both sides keeps the test in integers.

The pattern to keep

Step leaves…Meaning
only x changestrue line still within half a cell — flat move
x and y changetrue line drifted ≥ half a cell — diagonal move

Count the diagonal moves above: exactly 2, which is |By−Ay|. That is always true on a shallow line, and it is worth checking on the simulator until it feels obvious.

Code map. dx, dy, sx, sy, err are set once before the loop; e2 is recomputed every tick; the two ifs are the only decision in the whole algorithm. Everything else is bookkeeping.
